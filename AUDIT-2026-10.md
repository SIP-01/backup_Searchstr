# Security Audit — SIP-01/backup_Searchstr — 2026-10-20

## Summary
Light-plus sweep of backup_Searchstr (backup of 0xSearchstr: React/Vite frontend PLUS a self-hosted backend — Meilisearch, Nostr/clearnet/Tor/I2P crawlers, NIP-50 relay, Abuse API — via docker-compose). Last commit 2026-09-19. No committed live secrets found (placeholders only). Findings: 0 CRITICAL / 0 HIGH / 2 MEDIUM / 2 LOW. Highest risk: insecure-by-default backend credentials if anyone deploys this stack without editing .env.

## Findings
| ID | Severity | File/Area | Issue | Recommended fix |
|----|----------|-----------|-------|-----------------|
| B1 | MEDIUM | docker-compose.yml / .env.example | Weak defaults: `MEILI_MASTER_KEY: ${MEILI_API_KEY:-change-me}` and `ABUSE_ADMIN_TOKEN: ${ABUSE_ADMIN_TOKEN:-change-me}`. If deployed with defaults, the Meilisearch master key and the admin bearer token are the literal string `change-me`, while ports 7700 (Meilisearch) and 8080 (abuse API) are host-exposed. | Fail fast at startup when defaults are in use (refuse to boot), or generate random secrets; document firewalling 7700/8080 |
| B2 | MEDIUM | backend/abuse-api/src/index.ts | CORS `Access-Control-Allow-Origin: *` on every response including admin endpoints, with `Authorization` in allowed headers. Bearer auth gates the admin routes, so exploitation needs the token — but combined with B1's default token this is a cross-origin admin API. | Restrict CORS to the frontend origin; drop `*` when credentials/Authorization are in play |
| B3 | LOW | backend/abuse-api/src/index.ts (`/api/search`) | Meilisearch filter built by string interpolation from unvalidated `source`/`kind` query params (`kind = ${kind}`) — filter-expression injection (query manipulation, not RCE). | Validate `kind` as integer, allowlist/escape `source` |
| B4 | LOW | backend/abuse-api/src/index.ts (`isAdmin`) | Bearer token compared with `===` (not constant-time) — theoretical timing side-channel. | Use `crypto.timingSafeEqual` |
